# 权重语义兼容性判定标准

主技能规定权重适配的决策流程（何时保留行为、何时按新能力验收及如何记录）；本参考提供具体比对维度、反例和验证方法。名称匹配和 shape 匹配都只是线索，不是语义兼容证明。只有当源张量与目标张量在有效配置和实际计算图中承担相同运算职责，且索引/表示约定一致时，才可直接复用。无法证明的情况标记为“语义未确认”，不可静默加载并宣称兼容。

## 逐项比对维度

对每个候选参数、缓冲区及其必要元数据，从源模型与目标模型分别核对：

| 维度 | 要确认的事实 | 常见不兼容信号 |
| --- | --- | --- |
| 职责与路径 | 属于哪个模块/层/分支，在计算图中参与什么运算；输入、输出、残差/归一化位置是否相同？ | 同名模块被移动；原线性层改作门控/投影；同形参数实际服务不同分支。 |
| 轴与索引语义 | 每一维代表什么；权重是 `[out,in]` 还是转置布局；head、Q/K/V、gate/up、expert、分片或打包排列是否相同？ | 转置/拼接顺序改变；GQA/MQA 分组、padding、词表 token ID、专家编号或 shard 范围变化。 |
| 有效配置 | 层数、hidden/intermediate size、head 数、bias、激活、RoPE/position、norm、残差顺序等是否一致？ | 同名权重依不同配置解读；旋转维、rope scaling、norm epsilon 或 pre/post-norm 改变。配置虽不是权重，也会改变含义。 |
| 状态类型与绑定 | 是参数、固定 buffer、running statistic 还是缓存/导出状态？预期共享/tied alias 是否一致？ | buffer 变参数；共享 embedding/head 被拆分或反之；BN running stats 语义不同。 |
| 表示与数值约定 | dtype、量化格式、scale/zero-point、分组/轴、packing、舍入、稀疏/低秩表示和反量化规则是否一致？ | dtype 相同但 qparam/layout 不同；分组尺寸/量化轴变化；packed tensor 被当普通浮点矩阵。 |
| 分布与训练状态 | global/local shape、分片轴/rank 范围、复制/聚合规则匹配吗？optimizer state 的参数身份/顺序/形状/语义匹配吗？ | 并行拓扑变化、reshard 未执行、optimizer moment 对错参数或沿用于新形状。 |

## 分类与决策

1. **直接复用：** 上述适用维度均有证据一致，且目标路径按预期消费。记录源/目标版本、关键配置和必要的探针验证。冻结权重也要核对注册、前向和保存/加载；只对训练中预期可训练参数检查梯度及 optimizer 纳入。
2. **显式映射/转换：** 语义相同但名称/布局变化，或经过有依据的转换后对应。记录转换函数、轴/索引映射、假设、损失/舍入和验证。转置、重排、拼接拆分、分片合并不可只因元素数相等就认定有效。
3. **初始化/重置：** 新增、语义改变或不能可靠映射的参数/状态按预先说明策略初始化或重置。保持行为时不能用微调掩盖未解释的适配前漂移；能力改变时按目标门槛验收。
4. **排除/不适用：** 说明为何缺失或多余键按设计可排除，并验证目标路径不需要它。禁止用宽泛 `strict=False`、忽略 mismatched size 或过滤 key 代替逐项解释。
5. **未确认/阻塞：** 找不到配置、源布局、分片清单或可测试路径时，不宣称兼容；限制范围，停止不安全加载或改用隔离的小样本替代。

## 同名同形但语义不兼容的典型反例

- `q_proj.weight` 同为 `[d,d]`，但 head 排列、RoPE 作用维度或 grouped-query 头到 KV 头映射不同。
- `in_proj_weight` 同为 `[3d,d]`，但 Q/K/V 拼接顺序不同；拆分后每块形状相同也仍会错配。
- `fc1.weight` 同形，但一版用于普通 MLP，另一版按 gate/up 两段切分并经不同激活组合。
- `embed_tokens.weight` 同形，但 tokenizer/vocabulary token ID 顺序不同；尺寸相同无法证明每一行语义相同。
- LayerNorm/RMSNorm 参数同名同形，但归一化公式、epsilon、bias 或 pre/post-norm 结构不同。
- 同名量化 tensor 有同形整数载荷，但 scale/zero-point、group size、量化轴或 packing metadata 不同。
- rank-local 参数名与形状相同，但原并行 world size、global shard 范围或 expert/rank 映射不同。

## 行为验证

- **目标为保留旧行为：** 在微调前以固定输入/探针比较源模型与适配后目标模型。固定前处理、tokenizer/config、推理模式、精度、设备和随机条件；测前选定适用指标及容差，例如 logits/激活的 max absolute/relative error、归一化误差或任务输出差异。选择指标须贴合 dtype、数值范围和目标；报告全部实测，不以“输出看起来合理”替代比较。超差先查映射、初始化、配置或执行路径。
- **目标为改变能力：** 预先定义目标任务指标门槛和必要的非回归约束。新旧输出不同不本身构成失败，但每项复用/映射仍需语义依据，并按目标能力和必要回归验收。
- 分开报告：加载 API 完成、逐项 key/元数据审计、目标前向/序列化验证、适配前行为探针、训练后任务能力评估。它们是不同证据层级。

## 多版本链式迁移

当权重需经过 `v1 → v2 → v3 → target` 等多个中间版本：

- 保留原始可信 checkpoint 作为只读基准；记录每一跳的源/目标代码与配置 revision、转换工具版本、映射表、初始化/排除项、哈希/分片信息和可复现命令。不要只保留最后一个转换产物。
- 每一跳都分别做逐项语义审计和适配后探针；随后在最终 target 上做端到端探针与任务门槛。链上每一步的局部通过不能替代最终目标路径验证。
- 对可能有损的量化、裁剪、插值、低秩合并、重排或 dtype 转换，记录并测量每跳误差；不要假定误差必然累积，也不要假定后续步骤会抵消。避免重复执行有损转换，能从可信源直接迁移时，以同一探针比较直接路径与链式路径。
- 若中间版工具/配置缺失，或链中某跳只剩未知含义的产物，标注该跳为阻塞/未确认；不得通过最终加载成功倒推整条链兼容。
- optimizer/scheduler/RNG 状态分别审计；跨架构或多跳迁移时默认重建不兼容状态，只在参数身份、顺序、shape 与语义逐项证明一致后才保留。
