# 让结论不可辩驳：可复现性、参照系、等价性

> 前面三份 reference 讲**怎么不犯错**（审计、完整性、陷阱）。这份讲**怎么把结论做硬**——
> 一个结论要能被第三方接受，需要四根柱子。缺任一根，它只是"作者说它对"。
>
> 四条都来自实际做成的实验，不是方法论口号；每条附可执行的构造。

## 四根柱子

| 柱子 | 回答的问题 | 缺了会怎样 |
| --- | --- | --- |
| **① 管线自检** | 我的实现在已知答案上对吗？ | 分不清"没信号"与"实现错了" |
| **② 参照系** | 这个数字最大可能是多少？ | 不知道好坏的分母是什么 |
| **③ 零分布** | 随机情况会给出多少？ | 任何数字都"显著" |
| **④ 等价性** | 换台机器/换分段会变吗？ | 结果不可被他人复现 |

顺序也重要：**先 ① 再谈信号**。跳过 ① 直接看效应，是本文档所有失败模式里最常见的一条。

## ① 管线自检：先在已知答案上跑通

**问题**：真实数据给出"不显著"时，你无法区分三种情况——真的没效应、实现有 bug、数据坏了。

**构造**：在同一条代码路径上，先复现一个**已经确立的数字**。

真实案例：做 RSA 之前，先在已知的 THINGS-EEG 4D 数据上跑 200 类解码，得到
**0.0785 = 15.7× 随机**，与代码文档里记载的 **15.6×** 一致 ⇒ 说明解码实现是对的
⇒ 此后"不显著"只可能是 RSA 或数据的问题，不是解码器的问题。

三条纪律：

- **自检必须端到端**，不是零件测试。真实踩过：零件测试全绿，接进管线后暴露 **4 个形状 bug**。
- **自检要有独立来源的期望值**（文档、论文、上一个版本的产物），不能自己算一个再自己对。
- 自检失败时**先修实现，不要先解释数据**。反过来做会把 bug 写成科学发现。

**副产品**：自检常常顺手证明别的事。上例里逐窗解码剖面（0–100 ms 5.0×、**100–200 ms 10.3×**、
200–300 ms 8.8×、400 ms 后回到 1.0×）是教科书式刺激锁定剖面 —— 它同时确认了时间轴起点正确。

## ② 参照系：先找到分母

**问题**：`R² = 0.0196` 听起来很小，是大还是小？

**构造**：找一个**同类问题的公认上界**，把绝对数字变成比值。

真实案例（编码模型）：用其余 9 个被试的脑响应预测本被试 ⇒ **BBB 跨被试脑对脑上限**。
然后报 `img / BBB` 而不是单独的 `img`。实测 **1.03** —— 意味着模型特征已经达到
"另一个人的大脑"这一水平，`0.0196` 立刻有了意义。

参照系的三种来源：

| 来源 | 例 | 注意 |
| --- | --- | --- |
| **同问题的物理上界** | 跨被试预测（BBB）、分半信度上限 | 上界本身必须为正，否则是管线错误 |
| **更强的同类方法** | 更大模型、更长训练 | 打平也是结论（见下） |
| **被替换掉的旧实现** | 上一版脚本 | 必须同一口径 |

两条使用纪律：

- **上界为负 = 管线坏了，不是"没信号"**。BBB 为负说明跨被试对齐失败，此时任何"显著性"都不可信。
- **"更强的方法打平"是正面结论**。实测：ViT-H-14 vs ViT-B-32 在脑解码上打平 ⇒
  **144× 计算量换不来更好的脑解码**。这条比"我们用了更大的模型"有用得多。

## ③ 零分布：随机情况必须真的随机

**问题**：置换检验看起来是"非随机"检验，但它的有效性完全取决于置换的是不是该置换的东西。

真实案例（两个都踩过）：

| 写法 | 症状 | 根因 |
| --- | --- | --- |
| 置换**数据行** | 置换值与原值**完全相同**（都是 0.0515） | 下游按位置重建标签 ⇒ 把置换撤销了 |
| 置换**组内数值**（测离散度） | `ratio` 精确等于 **1.00**、`p` 精确等于 **1.000** | 组内标准差对组内置换**不变** |

**纪律**：

- 置换的对象必须是**产生结论的那个对应关系**。测"标签能否预测"就置换标签；
  测"分组是否影响离散度"就置换**分组**（伪标签），不是组内值。
- **置换后结果与原值逐位相同 ⇒ 置换无效**，不是"没有差异"。这是最强的自检信号。
- **零分布口径必须与观测口径一致**。真实案例：观测统计量是 `max_over_windows`，
  若零分布固定在"观测选中的那个窗"，窗口选择的向上偏置只作用在观测值上，p 值偏乐观。
  正确做法：**零分布也取 max_over_windows**（一次矩阵解本来就给出全部窗口，取 max 不额外花钱）。

**下限要写出来**：`p = 0.005` 在 200 次置换下是**最小可能值**；`p = 0.048` 在 20 次置换下同理。
报 p 时必须报置换次数，否则读者会以为是精确值。

## ④ 等价性：证明"在哪算都一样"

**问题**：结果跑在远端，分段执行、多台机器、多个 worker 实现。凭什么说它们等价？

**构造**：让判决**与执行环境无关**，然后逐位对拍。

真实案例（三件套）：

| 机制 | 做法 |
| --- | --- |
| **判决脚本冻结** | 判决脚本按 **SHA-256 校验后原样执行**；改的只能是"取哪些数据""怎么合并" |
| **随机数派生固定** | 判决脚本内所有随机数由**固定 seed** 派生，**与 session 名无关** ⇒ 同一单元在任何机器上算都逐位相同 |
| **三重交叉验证** | ① 同一单元在**两个不同 Job** 里各算一遍 → 逐位相同（`+1.8144886303238472`）② 两种 worker 实现 → 与单跑日志逐位一致 ③ **离线重算**（用判决脚本里的 `decide()` 从原始记录重算）→ 与云端**逐字一致** |

⇒ 结论：**分段执行与整轮执行逐位等价**。这句话一旦成立，"平台中途取消长 Job"就不再是风险。

**通用化**：任何"分段/分布式/重试"的执行方式，只要能证明
**判决函数是纯函数 + 随机数由内容派生 + 结果可离线重算**，就与一次性执行等价。

## ④b 独立复算：换实现，不是重跑

等价性证明"在哪算都一样"；**独立复算**证明"换个实现结论还在"。两者不能互相替代。

真实案例（同一结论经三套实现）：

| 维度 | 一审 | 二审 | 三审 |
| --- | --- | --- | --- |
| 数据划分 | 换扰动种子 | 未见组合（奇偶划分） | **换域**（槽位值域分割） |
| 探针 | SGD 逻辑回归 | 闭式岭回归 | 岭回归 + MLP + kNN 三族 |
| 被替换的结构件 | 两层 MLP | LayerNorm+GELU MLP | 残差 MLP + 门控 |
| 种子 | 0–4 | 1000–1004 | 2000–2004 |
| 容量 | 256 | 128/256/512 | 96/384（与上一审不重叠） |

**每审换掉全部自由变量**，只保留被审计对象本身。三套同向后可以说"经三套独立实现复现"——
**仍不能说"已证明"**。

另两条：

- **单一探针族不构成证据**：线性探针读不到非线性可解码的结构（实测 MLP 0.58 vs 线性 0.43）。
  至少两类（线性 + 非线性/非参数），并报**差值**。
- **换种子不是形式**：它把"结论依赖某次初始化"变成可检验的（≥4/5 同向）。

## ④c 配对：让差异只来自被研究的那个变量

**构造**：多档并列比较时，所有档共用同一初始化、同一批顺序、同一 seed，
产物里落**初始化哈希**，从产物层核对各档同值。

实测收益：三档共用初始化后，读数 `0.1504 / 0.1507 / 0.1500`（差 <0.5%）——
差异只能来自损失函数，这条很强。若不配对，同样的三档差异会被采样噪声淹没。

**参数等量**是配对的另一半：换任何一个组件都可能悄悄改变参数量，于是"哪个方案好"
与"哪个模型大"混在一起。判据：对着**真实模块**数参数并对齐到 <1%（公式极易漏项：
实测漏 `h²` 项偏差 44%、输出层重复计数偏差 6.4%）。

## 拼装顺序（可照抄）

```
1. 管线自检     同一条代码路径上复现一个已确立的数字（独立来源的期望值）
2. 参照系       找到同类问题的上界，报比值；上界须为正
3. 零分布       置换"产生结论的那个对应关系"；置换无效时结果逐位相同
                零分布口径 == 观测口径
4. 等价性       冻结判决（SHA-256）+ 随机数由固定 seed 派生 + 离线重算逐字一致
```

每一条都留下一个可检查的产物：自检的期望值与实测值、参照系的分母、置换次数与最小 p、三方对拍的具体数字。

## 两条容易漏掉的配套

**留出集的切法要按"独立单元"，不是按行**：图像编码实验里按**图像**切 5-fold，
同一图像的 80 次重复整折进出。按试次切会让测试图像出现在训练集 ⇒ R² 虚高。

**剔除样本要留痕**：某个样本的条件坏了就剔除，但必须写进产物（哪个、为什么、依据哪条判据）。
静默剔除等于选择性报告——即使剔除是对的，读者也无法复核。
