## 可迁移的工程模式

1. **明确模型边界与张量契约。** 跟踪真实前向图；让组件、特征提取与任务头的接口、形状及配置可检查。对中间特征或激活定义稳定名称与形状，而不要依赖脆弱的硬编码索引。参考 [Transformers 模型贡献指南](https://huggingface.co/docs/transformers/en/contributing)、[timm 特征提取](https://huggingface.co/docs/timm/en/feature_extraction) 与 [TransformerBridge 模型结构](https://transformerlensorg.github.io/TransformerLens/content/model_structure.html)。
2. **将验证拆成不同层次。** 视改动适用性分别做组件数值/形状检查、模型前向或 logits 与参考实现比较、checkpoint 加载/转换检查、以及任务级评测。某一层通过不能替代其他层，也不能单凭前向一致宣称质量或性能改善。torchtune 文档明确区分组件 parity、模型/checkpoint parity 与 recipe benchmark；该项目已于 2025 年停止活跃维护，其文档只作历史工程参考。[Overview](https://meta-pytorch.org/torchtune/0.6/overview.html)
3. **把权重加载/转换当作模型接口的一部分。** 审计缺失、多余、未使用的键及 shape/layout 转换；写清映射依据、配置与分片/复制假设，并通过代表性权重、往返加载或固定输入输出检查语义。不要以“加载函数未报错”替代兼容性结论。参考 [Transformers 权重转换指南](https://huggingface.co/docs/transformers/add_new_model)、[LitGPT 模型测试（commit `d28a00d`）](https://github.com/Lightning-AI/litgpt/blob/d28a00d8a0014d2c0a9038fcd6bcfdd30fad4368/tests/test_model.py)、[torchtune checkpoint 文档](https://meta-pytorch.org/torchtune/0.6/deep_dives/checkpointer.html) 与 [Megatron Core 概览](https://docs.nvidia.com/megatron-core/developer-guide/latest/get-started/overview.html)。
4. **比较替代执行路径。** 当改动涉及推理缓存、精度、融合算子或特征捕获时，使用固定输入与容差比较可比路径，例如缓存/非缓存生成、参考/优化 attention、不同 dtype 的输出；只捕获调试所需激活，避免无必要地缓存全部中间状态。参考 [LitGPT 测试（commit `d28a00d`）](https://github.com/Lightning-AI/litgpt/blob/d28a00d8a0014d2c0a9038fcd6bcfdd30fad4368/tests/test_model.py) 与 [TransformerLens 主示例](https://transformerlensorg.github.io/TransformerLens/generated/demos/Main_Demo.html)。
5. **把性能主张绑定到受控条件。** 固定并记录任务、数据、训练配方、步数/计算预算、硬件与关键配置；用基线和必要消融隔离单项改动，分别报告质量与适用的延迟、吞吐、内存。项目论文或 README 的数字依赖其任务与硬件，不能直接迁移为目标项目的收益。参考 [timm ResNet 训练程序研究](https://arxiv.org/abs/2110.00476) 与 [Megatron-LM 研究](https://arxiv.org/abs/2104.04473)；Megatron README 也披露其部分效率测量未训练至收敛。

## 项目实例与适用边界

| 项目 | 值得借鉴的具体模式 | 状态或边界 |
| --- | --- | --- |
| [Hugging Face Transformers](https://github.com/huggingface/transformers) | 先对照相近架构、说明必要差异；从配置实例化后做前向与模型集成测试；逐项处理 checkpoint 的缺失/多余键、尺寸不匹配和转换。来源：[贡献指南](https://huggingface.co/docs/transformers/en/contributing)、[新增模型指南](https://huggingface.co/docs/transformers/add_new_model)。 | 框架自己的抽象和贡献约定不必照搬；支持它们的是工程可读性与兼容性检查，不是某个架构更优的证据。 |
| [timm / PyTorch Image Models](https://github.com/huggingface/pytorch-image-models) | 分离 `forward_features` 与 head；验证声明的中间特征通道/降采样元数据与实际张量；将模型构造、权重载入和分类头调整明确分开。来源：[特征提取指南](https://huggingface.co/docs/timm/en/feature_extraction)、[Models API](https://huggingface.co/docs/timm/en/reference/models)。 | ResNet 论文结果仅适用于其报告的数据与训练条件；训练配方变化不可误归因于架构变化。 |
| [LitGPT](https://github.com/Lightning-AI/litgpt) | 用固定输入比较参考 logits，并验证缓存与非缓存生成路径；把 checkpoint 转换和短步数训练 smoke test 纳入验证。来源：[模型测试（commit `d28a00d8a0014d2c0a9038fcd6bcfdd30fad4368`；2026-10-15 核验）](https://github.com/Lightning-AI/litgpt/blob/d28a00d8a0014d2c0a9038fcd6bcfdd30fad4368/tests/test_model.py)、[快速教程（同一 commit）](https://github.com/Lightning-AI/litgpt/blob/d28a00d8a0014d2c0a9038fcd6bcfdd30fad4368/tutorials/0_to_litgpt.md)。 | 这些是可参考的测试实例，不证明其结构或配方普遍最优；按目标框架和版本改写。 |
| [torchtune](https://github.com/meta-pytorch/torchtune) | 以可组合的 PyTorch 组件实现模型；区分组件数值 parity、checkpoint/model parity 与训练 recipe 的 benchmark；把转换和端到端生成检查作为单独步骤。来源：[Overview](https://meta-pytorch.org/torchtune/0.6/overview.html)、[checkpoint 文档](https://meta-pytorch.org/torchtune/0.6/deep_dives/checkpointer.html)、[端到端流程](https://meta-pytorch.org/torchtune/0.6/tutorials/e2e_flow.html)。 | 官方仓库称项目于 2025 年结束活跃维护；所引 v0.6 文档为版本化历史资料，不代表当前维护建议。 |
| [nanoGPT](https://github.com/karpathy/nanoGPT) | 保持小型计算图易审计；对 GPT-2 权重映射明确检查键、shape 与矩阵转置；区分训练时完整 logits/loss 路径与生成时仅投影末位置的路径。来源：[模型实现（commit `3adf61e154c3fe3fca428ad6bc3818b27a3b8291`；2026-10-15 核验）](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py)、[训练实现（同一 commit）](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/train.py)。 | 仓库在 2025-11 更新中标为已弃用、仅作存档；README 也警告 OpenWebText 与 WebText 并非等价数据，历史 loss 数值不可作直接架构比较。 |
| [Megatron-LM](https://github.com/NVIDIA/Megatron-LM) | 区分可复用模型组件与示例训练程序；将参数分片、并行布局与 checkpoint 互操作视为显式契约；测量通信、内存和吞吐的联合权衡。来源：[仓库 README](https://github.com/NVIDIA/Megatron-LM)、[Megatron Core 概览](https://docs.nvidia.com/megatron-core/developer-guide/latest/get-started/overview.html)、[论文](https://arxiv.org/abs/2104.04473)。 | 并行策略与报告速度强依赖硬件、模型、序列长度和布局；效率测量不能证明任务质量改善，部分公开基准未训练至收敛。 |
| [TransformerLens](https://github.com/TransformerLensOrg/TransformerLens) | 以适配器映射原生模型结构到通用组件/激活 hook；验证 hook 名称与张量形状；用选择性缓存、早停和固定输入的数值比较控制诊断成本。来源：[模型结构](https://transformerlensorg.github.io/TransformerLens/content/model_structure.html)、[主示例](https://transformerlensorg.github.io/TransformerLens/generated/demos/Main_Demo.html)。 | 主要是可解释性/检查工具，并非优化结果证据；激活干预可检验局部因果假设，但不能替代目标任务评估。 |
| [MiniMind LLM](https://github.com/jingyaogong/minimind/tree/f659b55761b754d306bd140573493a6543cafd7f) | 将小型 Dense/MoE 模型、核心模块、tokenizer 与预训练/SFT 等流程作为从零实现 LLM 的教学案例；适合跟踪模型结构和训练入口如何衔接。来源：[固定提交 README](https://github.com/jingyaogong/minimind/blob/f659b55761b754d306bd140573493a6543cafd7f/README.md)、[许可证](https://github.com/jingyaogong/minimind/blob/f659b55761b754d306bd140573493a6543cafd7f/LICENSE)（commit `f659b55761b754d306bd140573493a6543cafd7f`）。 | README 将其定位为从零训练小型语言模型，关键模块/算法有原生实现；仍是特定教学项目与配方，不是通用效果或性能证明，也不构成默认技术栈。仓库许可证为 Apache-2.0；模型/数据等依赖须另核许可。 |
| [MiniMind-V](https://github.com/jingyaogong/minimind-v/tree/1862b633fc082a723e78dbead9777545f09d960c) | 参考其图像占位符到视觉编码、projector、语言主干的接口，以及冻结编码器、投影层和部分语言层的分阶段适配方式。来源：[固定提交 README](https://github.com/jingyaogong/minimind-v/blob/1862b633fc082a723e78dbead9777545f09d960c/README.md)、[许可证](https://github.com/jingyaogong/minimind-v/blob/1862b633fc082a723e78dbead9777545f09d960c/LICENSE)（commit `1862b633fc082a723e78dbead9777545f09d960c`）。 | 不应把“从 0 训练”理解为全部组件随机初始化端到端训练：该版本复用 MiniMind LLM 底座权重，SigLIP2 视觉编码器冻结；主要训练 projector，并按阶段/配置训练部分或全部 LLM 参数。仓库许可证为 Apache-2.0；外部编码器、权重与数据集许可须另核。 |

## 使用规则

- 先读目标仓库当前版本的实现、测试和配置，再选择适用的模式；不因某项目使用某 API 就迁移框架或新增依赖。
- 将外部论文、模型卡、项目代码和 checkpoint 只当作候选证据/假设来源，不当作目标仓库事实、默认方案或效果证明。对实际采用的参考记录来源链接、确切版本或 commit、许可证与适用限制；对 checkpoint 另记录发布者/来源、固定 revision、格式及校验依据。GitHub `main`/`master` 等可变分支引用优先改为含完整 commit SHA 的文件链接；无法固定时，记录分支/标签及该条来源的访问日期，不能只依赖整份文档的快照日期。未审查代码安全、权重加载安全和许可证兼容性前，不复制/执行外部实现或加载其权重。
- 把每条要检验的外部架构主张映射到目标仓库的具体文件/符号/配置、实际模型路径及一个可证伪的本地测试。外部论文/README 的指标只能作背景，不能替代本地基线、验收门槛或收益证据；效果结论须来自同一目标项目、同一任务与可比数据/配置/种子/资源条件下的实测，并在适用时用消融归因。
- 明确区分结构/接口正确、权重语义兼容、任务质量变化和运行效率变化；每项结论都需对应本任务的实际检查或评测证据。
